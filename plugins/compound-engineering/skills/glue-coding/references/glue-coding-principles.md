# 胶水编程核心原则速查

## 一句话定义

> 几乎完全复用成熟开源组件，通过最小量的"胶水代码"将它们组合成完整系统

## 五条铁律

1. **凡是能不写的就不写，凡是能少写的就少写**
2. **凡是能 CV 就 CV** - 复制使用经过社区检验的代码是正常工程流程
3. **站在巨人的肩膀上，而不是试图成为巨人**
4. **不修改原仓库代码** - 开源库作为黑盒使用
5. **自定义代码越少越好** - 只承担组合、调用、封装、适配

## 胶水代码的四种职责

```
组合 → 将多个库串联成流程
调用 → 封装统一的调用接口
封装 → 隐藏底层实现细节
适配 → 转换数据格式和协议
```

## 标准流程

```
明确需求 → 拆解子模块 → 搜索开源库 → 下载整理 → 按架构组织 → 编写胶水层
```

## 目录结构模板

```
project/
├── src/
│   ├── glue/           # 胶水代码（你写的部分）
│   │   ├── adapters/   # 适配器
│   │   ├── pipelines/  # 数据流管道
│   │   └── config/     # 配置管理
│   └── main.ts
├── third_party/        # 第三方库
└── package.json
```

## 开源库筛选标准

| 指标       | 推荐阈值                                  |
| ---------- | ----------------------------------------- |
| ⭐ Stars    | > 500（优先 > 1000），从高到低排序        |
| 🕐 最近更新 | < 12 个月                                 |
| 📜 许可证   | 大多数可用（仅排除 AGPL、Non-Commercial） |
| 📚 文档     | 有基本说明即可                            |

## 胶水编程 vs 传统开发

| 维度     | 传统开发 | 胶水编程 |
| -------- | -------- | -------- |
| 功能实现 | 自己写   | 复用开源 |
| 工作量   | 大       | 小得多   |
| 成功率   | 不确定   | 高       |
| 速度     | 慢       | 极快     |
| 重点     | 造轮子   | 组合轮子 |

## 核心价值

- **极高成功率** - 使用社区验证过的成熟代码
- **开发速度快** - 大量功能直接复用
- **降低成本** - 时间、维护、学习成本大幅减少
- **系统更稳定** - 依赖成熟框架而非个人实现
- **易于扩展** - 替换组件即可升级能力
- **与 AI 强配** - AI 辅助搜索、拆解、整合
