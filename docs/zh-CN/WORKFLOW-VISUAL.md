## 详细步骤分解

### Step 0: `/workflows:load` - 加载上下文

```
┌─────────────────────────────────────────────────────────┐
│  /workflows:load [可选: 自定义路径]                       │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  输入参数:                                               │
│  ├── 无参数 → 加载 docs/context/project-context.md      │
│  └── 有参数 → 加载指定路径                               │
│                                                         │
│  执行流程:                                               │
│  ┌────────────────┐                                     │
│  │ 检查文件存在？  │                                     │
│  └───────┬────────┘                                     │
│          │                                              │
│     是   │    否                                        │
│     ↓    └────────→ 搜索其他上下文文件                   │
│                      └─→ 多个？ → 列出供选择              │
│  ┌────────────────┐      └─→ 无？ → 提示创建             │
│  │ 读取并解析文件  │                                     │
│  └───────┬────────┘                                     │
│          ↓                                              │
│  ┌────────────────┐                                     │
│  │ 输出上下文摘要  │                                     │
│  │ • 项目名称     │                                     │
│  │ • 当前进展     │                                     │
│  │ • 恢复提示     │                                     │
│  └────────────────┘                                     │
│                                                         │
│  输出选项:                                               │
│  1. 继续上次工作                                         │
│  2. 查看详细进展                                         │
│  3. 开始新任务                                           │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

**适用场景**: 新会话开始、隔天继续开发、跨设备工作

### Step 1: `/workflows:brainstorm` - 探索需求

```
┌─────────────────────────────────────────────────────────┐
│  /workflows:brainstorm [功能描述]                        │
│                                                         │
│  ★ 可选参数: [P] - 激活 Party Mode 多代理讨论            │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  Phase 0: 评估需求清晰度                                 │
│  ┌────────────────────────┐                             │
│  │ 需求是否已足够清晰？     │                             │
│  └──────────┬─────────────┘                             │
│             │                                           │
│      是     │      否                                   │
│      ↓      │      ↓                                    │
│  建议跳转   │  继续 brainstorm                          │
│  /plan      │                                           │
│             ↓                                           │
│  Phase 1: 理解想法                                       │
│  ┌─────────────────────────────────────────────┐        │
│  │ 1.1 轻量级仓库研究                            │        │
│  │     → Task repo-research-analyst             │        │
│  │                                              │        │
│  │ 1.2 协作对话（AskUserQuestion 逐个提问）       │        │
│  │     • 多选题优先                              │        │
│  │     • 从广（目的）到窄（约束）                  │        │
│  │     • 直到清晰 OR 用户说"proceed"             │        │
│  └─────────────────────────────────────────────┘        │
│             ↓                                           │
│  Phase 2: 探索方案                                       │
│  ┌─────────────────────────────────────────────┐        │
│  │ 提出 2-3 个具体方案                           │        │
│  │ • 简要描述                                   │        │
│  │ • 优缺点                                     │        │
│  │ • 适用场景                                   │        │
│  │                                              │        │
│  │ ┌─────────────────────────────────┐          │        │
│  │ │ 用户可选择:                      │          │        │
│  │ │ • 方案 A/B/C                    │          │        │
│  │ │ • [P] Party Mode 多专家讨论  ←──┼──────────┼── ★    │
│  │ └─────────────────────────────────┘          │        │
│  └─────────────────────────────────────────────┘        │
│             ↓                                           │
│  ┌─────────────────────────────────────────────┐        │
│  │           Party Mode (可选增强)               │        │
│  │  ┌───────────────────────────────────────┐   │        │
│  │  │ 激活: 输入 [P] 或 "开启派对模式"        │   │        │
│  │  │ 退出: 输入 [E] 或 "结束派对"           │   │        │
│  │  │                                       │   │        │
│  │  │ 执行:                                 │   │        │
│  │  │ 1. 选择 2-3 个相关专家代理             │   │        │
│  │  │ 2. 多视角讨论（架构/业务/开发/安全）    │   │        │
│  │  │ 3. 代理可相互引用、质疑、补充          │   │        │
│  │  │ 4. 生成会话回顾（共识 + 分歧）         │   │        │
│  │  └───────────────────────────────────────┘   │        │
│  └─────────────────────────────────────────────┘        │
│             ↓                                           │
│  Phase 3: 记录设计                                       │
│  → 输出到 docs/brainstorms/YYYY-MM-DD-<topic>.md        │
│                                                         │
│  Phase 4: 交接                                           │
│  选项: 1. 进入 /plan  2. 继续探索  3. 稍后再来           │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

**Party Mode 适用场景**:
- 重大技术选型
- 多方利益权衡
- 复杂需求探索
- 事后复盘分析

### Step 2: `/workflows:plan` - 创建计划

```
┌─────────────────────────────────────────────────────────┐
│  /workflows:plan [功能描述]                              │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  Step 0: 想法细化                                        │
│  ┌────────────────────────┐                             │
│  │ 检查 docs/brainstorms/ │                             │
│  │ 是否有相关文档？        │                             │
│  └──────────┬─────────────┘                             │
│        有   │    无                                     │
│        ↓    └──→ 运行想法细化对话                        │
│  读取并使用                                              │
│  brainstorm 决策                                        │
│             ↓                                           │
│  Step 1: 本地研究（并行）                                │
│  ┌─────────────────────────────────────────────┐        │
│  │ Task repo-research-analyst ─┬─→ 仓库模式研究 │        │
│  │ Task learnings-researcher ──┴─→ 历史经验搜索 │        │
│  └─────────────────────────────────────────────┘        │
│             ↓                                           │
│  Step 1.5: 研究决策                                      │
│  ┌────────────────────────────────────────┐             │
│  │ 高风险主题（安全/支付/外部API）？        │             │
│  │     YES → 必须外部研究                  │             │
│  │     NO  → 检查本地上下文是否足够         │             │
│  │           足够 → 跳过外部研究           │             │
│  │           不足 → 进行外部研究           │             │
│  └────────────────────────────────────────┘             │
│             ↓ (条件性)                                   │
│  Step 1.5b: 外部研究（并行）                             │
│  ┌─────────────────────────────────────────────┐        │
│  │ Task best-practices-researcher              │        │
│  │ Task framework-docs-researcher              │        │
│  └─────────────────────────────────────────────┘        │
│             ↓                                           │
│  Step 2: 任务拆解（Bite-Sized 格式 - 必须遵循）          │
│  ┌─────────────────────────────────────────────┐        │
│  │ ⚠️ 铁律: 每个任务 2-5 分钟可完成              │        │
│  │                                              │        │
│  │ 每个任务必须包含:                             │        │
│  │ • 文件路径（确切，含行号）                    │        │
│  │ • 具体操作步骤                               │        │
│  │ • 完整代码（非伪代码）                        │        │
│  │ • 验证命令                                   │        │
│  └─────────────────────────────────────────────┘        │
│             ↓                                           │
│  Step 3-6: 结构规划、SpecFlow分析、详细级别选择、格式化   │
│             ↓                                           │
│  输出: docs/plans/YYYY-MM-DD-<type>-<name>-plan.md      │
│             ↓                                           │
│  后续选项:                                               │
│  ┌─────────────────────────────────────────────┐        │
│  │ 1. 打开计划文件                              │        │
│  │ 2. /deepen-plan - 并行研究增强               │        │
│  │ 3. /plan_review - 多代理评审                 │        │
│  │ 4. /workflows:work - 开始执行 ←────────────────       │
│  │ 5. 创建 GitHub Issue                        │        │
│  │ 6. 简化计划                                  │        │
│  └─────────────────────────────────────────────┘        │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

**计划详细级别**:
| 级别         | 适用场景           |
| ------------ | ------------------ |
| MINIMAL      | 简单 bug、小改进   |
| MORE（标准） | 大多数功能         |
| A LOT        | 重大功能、架构变更 |

### Step 3: `/workflows:work` - 执行计划

```
┌─────────────────────────────────────────────────────────┐
│  /workflows:work [计划文件路径]                          │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  Phase 1: 快速启动                                       │
│  ┌─────────────────────────────────────────────┐        │
│  │ 1. 读取计划并澄清                            │        │
│  │ 2. 检测 UI/前端任务 ──→ 自动加载设计技能      │        │
│  │ 3. 设置环境（分支/worktree）                  │        │
│  │ 4. TodoWrite 创建任务列表                    │        │
│  └─────────────────────────────────────────────┘        │
│             ↓                                           │
│  ╔═════════════════════════════════════════════════╗    │
│  ║            ★ 自动执行模式检测 ★                  ║    │
│  ║                                                 ║    │
│  ║  统计 TodoWrite 任务数量:                       ║    │
│  ║                                                 ║    │
│  ║     任务数 = 1          任务数 ≥ 2             ║    │
│  ║         │                    │                 ║    │
│  ║         ↓                    ↓                 ║    │
│  ║  ┌─────────────┐    ┌──────────────────┐      ║    │
│  ║  │  标准模式    │    │ Subagent-Driven │      ║    │
│  ║  │             │    │      模式        │      ║    │

│  ║  └─────────────┘    │ 每3任务检查点   │      ║    │
│  ║                     └──────────────────┘      ║    │
│  ╚═════════════════════════════════════════════════╝    │
│             ↓                                           │
│  Phase 2: 执行                                           │
│                                                         │
│  【标准模式】                【Subagent-Driven 模式】    │
│  ┌──────────────┐           ┌────────────────────────┐  │
│  │ while(tasks):│           │ batch_size = 3         │  │
│  │  • 标记进行中 │           │                        │  │
│  │  • 读取引用   │           │ for task in batch:     │  │
│  │  • 匹配模式   │           │  ┌────────────────┐    │  │
│  │  • 实现代码   │           │  │ 子代理执行任务  │    │  │
│  │  • 写测试     │           │  └───────┬────────┘    │  │
│  │  • 运行测试   │           │          ↓             │  │
│  │  • 标记完成   │           │  ┌────────────────┐    │  │
│  │  • 增量提交   │           │  │ Stage 1:       │    │  │
│  └──────────────┘           │  │ 规范合规审查   │    │  │
│                              │  │ (spec-compliance)│   │  │
│                              │  └───────┬────────┘    │  │
│                              │          ↓             │  │
│                              │  ┌────────────────┐    │  │
│                              │  │ Stage 2: (可选) │    │  │
│                              │  │ 代码质量审查   │    │  │
│                              │  └───────┬────────┘    │  │
│                              │          ↓             │  │
│                              │  人工检查点（每3任务）  │  │
│                              │  → 继续/审查/停止       │  │
│                              └────────────────────────┘  │
│             ↓                                           │
│  Phase 3: 质量检查                                       │
│  ┌─────────────────────────────────────────────┐        │
│  │ • 运行测试套件                               │        │
│  │ • 运行 linting                              │        │
│  │ • UI 检查（如适用）                          │        │
│  │ • 可选: 调用 reviewer agents                │        │
│  └─────────────────────────────────────────────┘        │
│             ↓                                           │
│  Phase 4: Ship It                                       │
│  • 创建提交                                             │
│  • 截图上传（UI 变更必须）                               │
│  • 创建 PR                                              │
│  • 通知用户                                             │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

**Subagent-Driven 优势**:
| 问题       | 单代理           | Subagent         |
| ---------- | ---------------- | ---------------- |
| 上下文污染 | 任务越多质量越差 | 每任务新鲜上下文 |
| Token 成本 | 累积增长         | 精确控制         |
| 首次成功率 | ~40%（后期）     | ~95%（恒定）     |

**Codex 审核前提条件**:
- 安装 Codex CLI: `npm install -g @openai/codex`
- 首次登录: `codex`（交互式）

**使用示例**:
```bash
/workflows:review              # 仅 Claude 审核
```

## 条件分支快速参考

### `/workflows:work` 自动模式选择

```
TodoWrite 任务数 = 1  → 标准模式（单代理直接执行）
TodoWrite 任务数 ≥ 2 → Subagent-Driven 模式
                        ├── 每任务新子代理
                        ├── 两阶段审查
                        └── 每 3 任务人工检查点
```

### `/workflows:plan` 外部研究决策

```
高风险主题（安全/支付/外部API）? → 必须外部研究
本地上下文充足?                 → 跳过外部研究
不确定/陌生领域?                → 进行外部研究
```

### `/workflows:review` 条件代理

```
PR 包含 db/migrate/*.rb? → 运行 data-migration-expert
                           + deployment-verification-agent
```
