# Brainstorm: 在 /workflows:brainstorm 中集成 [C][G] 外部咨询

**日期：** 2026-02-04
**状态：** 已确认

## 我们要做什么

在 `/workflows:brainstorm` 命令中集成 `[C]`（Codex）和 `[G]`（Gemini）可选参数，让用户在方案探索阶段可以调用外部 AI 工具来"挑战"Claude 提出的方案，寻找最优解。

## 为什么这个方案

### 语义定义

- **Review 中的 [C][G]**：代码审核（输入是 git diff）
- **Brainstorm 中的 [C][G]**：方案咨询（输入是讨论中的方案）

### 触发时机

Phase 2（探索方案）结束后、Phase 3（捕获设计）之前。此时 Claude 已提出 2-3 个方案，有了具体内容才能让外部工具有效评估。

### 与 [P] 的关系

三者正交、互不冲突：
- `[P]` = Claude 内部多视角讨论（派对模式）
- `[C]` = Codex 外部第二意见
- `[G]` = Gemini 外部第二意见

## 关键决策

1. **仅修改 brainstorm.md 一个文件**，约 85 行新增
2. **参数解析复用 review.md 的模式**
3. **调用方式用直接 CLI 调用**（不走审核脚本），类似 `/codex` 和 `/gemini` 命令
4. **结果整合进 brainstorm 文档**的"外部咨询"小节

## 实现要点

| 改动点 | 内容 | 行数 |
|--------|------|------|
| description 更新 | 加入 `[C][G]` 标识 | 1 |
| 参数解析 | Phase 0 加入 [C][G] 检测 | ~10 |
| Phase 2.5 新增 | Codex/Gemini 方案咨询步骤 | ~60 |
| Phase 3 微调 | 文档中整合外部咨询结果 | ~15 |

## 开放问题

无。方案已确认。
