# 胶水编程（Glue Programming）深度分析

## 分析背景

审视本项目（compound-engineering-plugin-private）与全局 CLAUDE.md 中的胶水编程原则的关系，评估执行效果和潜在冲突。

## 核心发现

### 1. 胶水编程的定义位置

```
┌────────────────────────────────────────────────┐
│ 第1层：全局 ~/.claude/CLAUDE.md（用户偏好）      │
│ → 胶水编程定义在这里                             │
│ → 标记为「默认生效」，所有项目自动生效            │
│ → 定义了搜索标准、禁止行为、工作流整合            │
└────────────────────────────────────────────────┘
                      ↓
┌────────────────────────────────────────────────┐
│ 第2层：项目 ./CLAUDE.md                         │
│ → ❌ 没有提及胶水编程（文档断层）                 │
└────────────────────────────────────────────────┘
                      ↓
┌────────────────────────────────────────────────┐
│ 第3层：插件 plugins/.../CLAUDE.md               │
│ → ❌ 也没有提及胶水编程（文档断层）               │
└────────────────────────────────────────────────┘
                      ↓
┌────────────────────────────────────────────────┐
│ 第4层：glue-coding Skill                       │
│ → ✅ 唯一明确承认双层设计的地方                   │
└────────────────────────────────────────────────┘
```

**结论**：胶水编程是用户的个人规范，不跟随项目走，其他开发者看不到。

### 2. 项目执行评分

| 指标 | 评分 | 证据 |
|------|------|------|
| 避免重复造轮子 | 10/10 | 没有自定义算法、测试框架、git实现 |
| 使用现有工具 | 10/10 | git CLI、gh CLI、Codex、Gemini、Context7、rclone |
| 最小化自定义代码 | 10/10 | ~900行 Python 包装器 / ~13000行总量 |
| 编排为主 | 10/10 | 28命令、20技能、28代理全是编排层 |
| 无 Mock/Stub | 10/10 | 所有集成使用真实库/CLI |

**总结**：项目本身是教科书级别的胶水编程实践，但文档没有说明这一点。

### 3. 识别的问题

#### 问题 A：文档断层
项目 CLAUDE.md 和插件 CLAUDE.md 都没有提及胶水编程，缺少设计哲学说明。

#### 问题 B：不跟随项目
胶水编程放在全局用户偏好，其他人 clone 项目时看不到。

#### 问题 C：工作流缺少主动提醒
`/workflows:plan` 和 `/workflows:work` 没有主动检查「有没有现成的库」。

#### 问题 D：隐性张力
全局 CLAUDE.md 说「只做编排」，但本项目的工作就是创建编排组件，需要明确区分。

### 4. CC Switch 与提示词管理

CC Switch 管理 `~/.claude/CLAUDE.md`（全局），但不管理 `~/.claude/rules/`。

**选定方案（方案 A：保持简单）**：
- 全局 CLAUDE.md 不动（CC Switch 云同步）
- 项目级 `.claude/rules/glue-programming.md`（Git 同步）
- 换电脑零额外操作

### 5. Claude Code 提示词层级完整图

| 层级 | 路径 | 同步方式 |
|------|------|----------|
| 系统提示词 | 内置（不可修改） | — |

## 决策记录

| 决策 | 选择 | 原因 |
|------|------|------|
| 同步方案 | 方案 A（保持简单） | CC Switch 管全局，Git 管项目，换电脑零成本 |
| 胶水编程位置 | 全局 + 项目 Rules 双层 | 全局是个人偏好，项目 Rules 跟随 Git |
| 工作流整合 | 在 brainstorm 和 plan 中加检查点 | 被动规则→主动提醒 |
